# 27B JSON Base 的 RA50 并发对比

实验 ID：`ra50-qwen27b-json-c124-100step-v1`。同一 AirSim 23 场景中的 4 架命名无人机共享一个 27B FP8 vLLM 服务，分别使用 1、2、4 个工作线程执行完整的同一 RA50（每组 50 条、最多 100 步）。每条任务一次一步；线程间请求并行到达 vLLM，各任务的图像历史、动作历史、位置及指标独立。

先运行四任务、两步的真实 preflight，确认四机车辆名、位姿更新、图像刷新和 JSON 模型接口，再执行完整对比：

```bash
bash scripts/run_ra50_multidrone.sh experiments/ra50_27b_preflight.json outputs/ra50_preflight_UNIQUE
bash scripts/run_ra50_multidrone.sh experiments/ra50_27b_c124.json outputs/ra50_multidrone_UNIQUE
```

启动器先要求干净的已提交工作区并写入 manifest，再启动专用模型服务及单个仿真；端口占用时拒绝启动，不结束已有进程。模型和仿真进程退出时释放各自的进程组。源代码和有效运行参数分别有提交号及配置哈希。

固定设置：100 步、3 张历史图、1920×1080 RGB、最近 10 个动作、JSON action/reason 输出、贪心生成、关闭思考模式，128 输出 token 上限。三组均关闭前缀和图像处理器缓存，排除重复任务缓存造成的假加速，每组前执行相同的四请求预热。统计单独记录取图、PNG 编码、首字等待及模型总请求耗时。

GPU 1 同时运行 Vulkan 仿真和 27B；模型显存预算 76%，最大 4 个活跃序列。仿真配置始终有四架无人机，未执行任务时停放在场景外。所有无人机具有相同初始坐标原点；每个设置位姿和取图 API 必须显式指定 vehicle_name，并验证实际位姿。

为避免任一无人机的物理时钟影响其他任务，评测使用 ExternalPhysicsEngine 消除重力漂移，保持场景更新并直接设置无人机位姿；设置后等待实际位置回读一致才取图。仅启用 RGB，关闭未用于评测的 lidar。三组保持这些设置相同；它们与旧版单机仿真并非严格相同。其他活动无人机可能出现在同一场景图像中，因此成绩也需要核对，不能只看吞吐。

prompt 为新的 `ra50-json-base-v1`，不声称复现未归档的 7 月 8B prompt。这是 27B 同策略下的并发对比，不是模型间公平比较。

每组生成 `ra50_cN.jsonl`、`ra50_cN_summary.json`，以及累计 `comparison.json`。主要指标：完整任务/小时、动作/秒、平均步数、NE、SR、OSR、SPL。吞吐速度比以完整任务/小时计算，同时报告动作/秒，避免少走步造成的假加速；单轮 50 条不是重复测速的统计置信结论。

2026-10-06 真实 preflight 已通过：4 个独立车辆、4 条任务各 2 步，共 8 次有效 JSON 模型请求；车辆位姿及相机刷新正常，退出后原仿真配置恢复，专用端口和显存释放。预检源提交 `dfd005cb9a9ff3ac06cef496e13f0e3ad5ee3891`（与 GitHub `8eec8da4c9bc609e0c7b117ea4ddb9a3c433a487` 源文件树一致）。短预检不作为 RA50 成绩或正式加速结果。

用户随后取消每组完整 50 条的长跑（单机组已完成 5 条），改用 `experiments/ra50_27b_short_c124.json`：相同前 4 条 RA50 任务，1/2/4 并发各最多 10 步。短跑只用于端到端吞吐比较，不作为导航成绩。重点比较动作/秒，并同时报告总动作数与墙钟时间；STOP 可使任务提前结束，三组实际工作量须核对。
